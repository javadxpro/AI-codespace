# KIMIA روی PS4 (لینوکس)

خلاصه: **PS4 یک کامپیوتر x86-64 است و موتور کیمیا C++17 قابل‌حمل است**؛ پس به
«پورت» نیاز ندارد — فقط به یک مسیر بیلدِ headless که به GPU و پنجره تکیه نکند.
این سند همان مسیر را توضیح می‌دهد.

## چرا بدون GPU؟

روی لینوکسِ PS4 درایور شتاب‌سخت‌افزاری (RadeonSI/AMDGPU) وصله‌ای، تجربی و قفل
به کرنل خاصی است و ممکن است ناپایدار باشد. به‌جای قمار روی آن، کیمیا از مسیر
**تضمینی** خودش استفاده می‌کند:

- **رسترایزر نرم‌افزاری** (`renderSoftware`) — بدون هیچ GPU‌ای کار می‌کند.
- **WebViewer** — بازی/ویرایشگر را روی یک پورت HTTP سرو می‌کند؛ از مرورگرِ
  گوشی یا کامپیوتر دیگری روی همان شبکه وصل می‌شوی. یعنی خودِ PS4 بدون مانیتور
  هم اجرا می‌شود و «صفحهٔ نمایش» آن، مرورگرِ گوشی توست.

این دقیقاً همان بیلدی است که روی Termux اندروید استفاده می‌شود
(`-DKIMIA_ENABLE_SDL2=OFF`)، و همین بیلد با **۴۶۸/۴۶۸ تست** روی لینوکس x86-64
تأیید شده است.

## شرط‌ها (قبل از شروع بدان)

- فقط روی فریمور قابل اکسپلویت. **فریمور 9.00** (مال تو) یکی از پایدارترین‌هاست.
- جیلبریک **ماندگار نیست**: بعد از هر ریبوت باید دوباره از مرورگر PS4 اجرا شود
  (گاهی چند بار تلاش لازم است). لودر لینوکس را همان سایتت اجرا می‌کند.
- وارانتی باطل می‌شود و PSN/آنلاین از دست می‌رود.
- CPU جگوار (۱.۶ گیگاهرتز) **کند** است: بیلدِ کامل ممکن است نیم‌ساعت به بالا طول
  بکشد و رندر نرم‌افزاری در رزولوشن پایین اجرا می‌شود. برای «توسعهٔ جدی» بهترین
  ترکیب این است: روی PC کد می‌زنی/بیلد می‌کنی، و PS4 را برای اجرای سریعِ همان
  باینری‌های headless نگه می‌داری.

## گام ۱ — لینوکس را بالا بیاور

۱. PS4 را روی فریمور 9.00 نگه دار و DNS را طوری بگذار که آپدیت خودکار نزند.
۲. با سایت/متد خودت جیلبریک را اجرا کن و payload «Linux» را بار کن
   (مثلاً گزینهٔ `Linux/1GB` — یک گیگ رم به GPU اختصاص می‌دهد و بقیه برای لینوکس).
۳. توزیع آمادهٔ PS4 (مثل **psxitarch** که Arch-based است) را روی USB/SSD نصب کن.
   یک ISO معمولی اوبونتو مستقیم بوت نمی‌شود؛ باید بیلد مخصوص PS4 باشد.

## گام ۲ — گرفتن کد

```bash
git clone --branch arena/01a080a4-ai-codespace https://github.com/javadxpro/AI-codespace.git
cd AI-codespace
```

> روی شاخهٔ `main` گیت‌هاب فقط اسکلت هست؛ حتماً با `--branch` کلون کن.

## گام ۳ — بیلد (یک دستور)

```bash
bash Tools/ps4_build.sh
```

اسکریپت خودش ابزار گم‌شده را نصب می‌کند (pacman/apt/dnf را تشخیص می‌دهد)،
با `-DKIMIA_WERROR=ON` و `-DKIMIA_ENABLE_SDL2=OFF` (headless) می‌سازد و تست‌ها را
اجرا می‌کند. گزینه‌ها:

```bash
bash Tools/ps4_build.sh --run          # بعد از بیلد، سرور را اجرا کن
bash Tools/ps4_build.sh --clean        # build-ps4/ را پاک کن
bash Tools/ps4_build.sh --port=9000    # پورت دیگر
```

## گام ۴ — اجرا و اتصال از گوشی

```bash
./build-ps4/bin/kimia_world --port 8080 --bind 0.0.0.0 --auth CHANGE_ME \
  --profiles build-ps4/bin/profiles
```

آدرس PS4 را پیدا کن:

```bash
ip addr | grep 'inet '
```

سپس در مرورگرِ گوشی/کامپیوترِ روی همان شبکه:

- **`http://<IP-PS4>:8080/?token=CHANGE_ME`** — خودِ بازی
- **`http://<IP-PS4>:8080/bench?token=CHANGE_ME`** — ویرایشگر KIMIA Editor

`--bind 0.0.0.0` یعنی کل شبکهٔ محلی می‌تواند وصل شود (بدون آن فقط داخل خودِ PS4
دیده می‌شود) و `--auth` با یک token ساده جلوی دسترسیِ غریبه‌ها را می‌گیرد.
پورت 8080 را روی روتر NAT/فوروارد نکن — فقط LAN.

## GPU: فعال کردن شتاب سخت‌افزاری (اختیاری ولی بهتر)

رندر نرم‌افزاری همیشه کار می‌کند، ولی اگر بخواهی GPUِ خودِ PS4 (چیپ GCN به اسم
**Liverpool**) را درگیر کنی، سه شرط باید هم‌زمان درست باشند — و **موتور هیچ
تغییری لازم ندارد**؛ خودش وقتی این سه تا باشند مسیر GL سخت‌افزاری را برمی‌دارد:

1. **کرنل**: درایور `amdgpu`/`radeon` که Liverpool را بشناسد. کرنل‌های PS4
   وصله‌دارند (Belize: 5.15 یا 6.6 از crashniels؛ Aeolia/Baikal بیلد خودشان).
2. **Mesa**: بیلدی که RadeonSI آن Liverpool را بشناسد (نسخه‌های وصله‌دار
   fail0verflow/psxita؛ ریپوی psxita برای توزیع‌های arch-based).
3. **کتابخانه‌ها**: `libGL.so.1` و `libEGL.so.1` روی دیسک باشند تا موتور آن‌ها را
   با dlopen پیدا کند.

### بررسی وضعیت (یک دستور)

```bash
bash Tools/ps4_gpu.sh
```

این اسکریپت سه لایه را گزارش می‌کند (کرنل، Mesa، و پروب خودِ موتور) و اگر کم
باشد، فرمان نصب را چاپ می‌کند. نسخهٔ `--install` هم سمت کاربر (Mesa/libGL) را
خودش نصب می‌کند:

```bash
bash Tools/ps4_gpu.sh --install
```

### پروب مستقیم موتور

```bash
./build-ps4/bin/kimia_world --gpuinfo
```

خروجی صادقانه است: `EGL context (3.3): yes` + نام رندرر (`AMD Radeon...`) یعنی
GPU زنده است و `kimia_world` از آن استفاده می‌کند؛ خروجی `SOFTWARE` یعنی هنوز
یکی از سه شرط بالا ناقص است. همین وضعیت در خط شروع هم دیده می‌شود:
`GL: yes (AMD Radeon ...)` یا `GL: no (software)`.

> **انتظار واقع‌بینانه**: حتی با GPU فعال، CPU جگوار کند است — GPU رندر را
> سریع می‌کند، نه بیلد را. و درایور PS4 «وصله‌ای و تجربی» است؛ اگر ناپایدار
> بود، مسیر نرم‌افزاری همیشه پشتیبانِ قابل‌اتکا باقی می‌ماند.

## نکته‌های عملی

- **شاخهٔ درست**: اسکریپت هم مثل `termux_build.sh` اگر روی `main` باشی، خودش به
  شاخهٔ موتور می‌رود.
- **کندی بیلد**: اگر می‌خواهی روی PS4 مستقیم بیلد نکنی، روی هر لینوکس x86-64
  دیگر با همین اسکریپت بیلد کن و پوشهٔ `build-ps4/` را روی PS4 کپی کن — باینری‌ها
  ELF x86-64 معمولی‌اند و با هم جابجا می‌شوند.
- **ریتریس آفلاین** (`kimia_raytrace`) هم در همین بیلد هست و تمام CPU است — روی
  PS4 اجرا می‌شود، فقط صبور باش.
