# انتشار نسخهٔ آفلاین (Tools/package_release.sh)

«نسخهٔ آفلاین» یعنی یک پوشهٔ **خودکفا** که بازیکن کپی می‌کند، باز می‌کند و
با **یک دستور** اجرا می‌کند — بدون کامپایلر، بدون Git، بدون اینترنت. آفلاین
در هر دو معنا: نه هنگام بازی به شبکه نیاز دارد، نه بازی آنلاین دارد.

```bash
bash Tools/package_release.sh                 # همهٔ بازی‌ها در یک بسته
bash Tools/package_release.sh --game=golf     # فقط گلف
bash Tools/package_release.sh --out=/tmp/rel  # جای خروجی
```

## داخل بسته چیست

```
kimia-golf-0.3.0/
  kimia_world        خود بازی — یک باینری بدون وابستگی
  play.sh            اجرای یک‌دستوره (پورت را هم می‌گیرد: sh play.sh 9000)
  profiles/          فایل‌های متنی بازی‌ها (با ویرایش‌شان بازی عوض می‌شود)
  worlds/            دنیاهای بازیکن اینجا ذخیره می‌شوند
  assets/            بازیکن OBJ/FBX خودش را اینجا می‌گذارد
  licenses/          لایسنس کتابخانه‌های آزاد (THIRD-PARTY.txt)
  README.txt         راهنمای فارسی بازیکن
  VERSION.txt        نسخهٔ موتور + کامیت Git + زمان ساخت
  MANIFEST.txt       sha256 هر فایل بسته
```

**قاعدهٔ محتوایی رعایت می‌شود:** بسته هیچ زمین یا مرحلهٔ آماده‌ای ندارد.
چیزی که منتشر می‌شود **بازی‌سازِ** گلف است به‌علاوهٔ پروفایل گلف؛ زمین را
خود بازیکن با منوها می‌سازد یا فایل `.kimia` خودش را باز می‌کند.

## اسکریپت چه تضمین‌هایی می‌دهد

اسکریپت عمداً سخت‌گیر است — بستهٔ خراب بدتر از نبودِ بسته است:

1. **بیلد Release با `-DKIMIA_WERROR=ON`**؛ اگر حتی یک اخطار باشد بسته‌بندی
   **رد می‌شود** (`0 warnings` یا مرگ).
2. **کل سوئیت تست اجرا می‌شود**؛ از درخت قرمز هرگز بسته ساخته نمی‌شود.
   (`--skip-tests` فقط برای بسته‌بندی دوبارهٔ درختی که همین الان تست شده.)
3. **ردیابی**: `VERSION.txt` کامیت را می‌نویسد و اگر درخت کامیت‌نشده باشد
   صریحاً `(uncommitted changes)` می‌زند؛ `MANIFEST.txt` sha256 همه چیز را
   دارد، پس هر بسته به یک کامیت مشخص برمی‌گردد.
4. **دود-آزمایی خودِ بسته** (نه درخت بیلد): بسته روی یک پورت یدکی اجرا
   می‌شود، `/menu` واقعاً باید جواب فارسی بدهد، و تنها بعد از آن آرشیو
   ساخته می‌شود. سرورِ آزمایش با SIGTERM و سپس SIGKILL قطعاً بسته می‌شود
   (بازی SIGINT/SIGTERM را می‌گیرد، پس یک `kill` ساده کافی نبود و پورت را
   نشت می‌داد — این باگ در همین مرحله پیدا و رفع شد).

## چرا بدون `profiles/` هم بازی می‌شود

`loadProfiles(dir)` اول پنج پروفایل **داخلی** را می‌دهد و بعد فایل‌های پوشه
را رویشان اعمال می‌کند. یعنی حتی اگر بازیکن پوشهٔ `profiles/` را پاک کند،
بازی باز می‌شود و هر پنج بازی در منو هستند — بسته نمی‌تواند بی‌صدا خراب
شود. فایل‌های پوشه راهِ **تنظیم مجدد** بدون C++ هستند
([Profile.md](Profile.md)).

## `kimia_world` روی خط فرمان

```
kimia_world [options]
  --port N          پورت وب (پیش‌فرض 8080)
  --world FILE      فایل دنیا برای ذخیره/بارگذاری
  --assets DIR      پوشهٔ OBJ/FBX قابل جای‌گذاری
  --profiles DIR    پوشهٔ *.kimiaprofile (بازی‌های داخلی بدون آن هم هستند)
  --version         چاپ نسخه
  --help            همین متن
```

گزینهٔ ناشناخته یا ناقص (مثلاً غلط تایپی `--porrt 9000`) **بی‌صدا نادیده
گرفته نمی‌شود**: پیام خطا و راهنما چاپ می‌شود و برنامه با کد ۲ بیرون
می‌آید. پیش از این، بازی بی‌صدا روی پورت اشتباه بالا می‌آمد و `--help`
اصلاً پیاده نشده بود (تلاش می‌کرد سرور را بالا بیاورد و می‌مرد) — هر دو در
همین مرحله رفع شدند، طبق قاعدهٔ «هیچ no-op خاموش».

## آزمایش واقعی این مرحله

بسته ساخته شد، در پوشهٔ دیگری باز شد و **مثل یک بازیکن** اجرا شد:
`sh play.sh` → منو در مرورگر → «دنیای جدید» → «گلف کیمیا» → سوراخ و توپ از
کاتالوگ → PLAY → شوت واقعی با نگه‌داشتن «شوت» (قدرت ۶۹٪، ضربه ثبت شد) →
«ذخیره» → فایل در `worlds/my_world.kimia` نوشته شد (با خط `# profile wind`)
→ بازی بسته و دوباره باز شد → «باز کردن دنیا» → همان زمین با سوراخ و توپ
برگشت.
