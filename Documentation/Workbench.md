# KIMIA Workbench — رابط کاربری ویرایشگر

`http://127.0.0.1:8080/bench`

عمداً کپی هیچ ویرایشگر دیگری نیست: واژگانش از **کارگاه** آمده نه از
استودیوی فیلم‌سازی. این هم اسم‌ها را متمایز می‌کند و هم دقیق‌تر توصیف
می‌کند که هر تکه چه‌کار می‌کند.

| نام ما | یعنی چه |
|---|---|
| **Bench** | کل صفحهٔ ویرایشگر |
| **Rack** | فهرست همه‌چیز در دنیا |
| **Dossier** | پنل توصیف یک جسم |
| **Fittings** | قطعاتی که به جسم پیچ می‌شوند (فیزیک) |
| **Labels** | برچسب‌هایی که به یک **گروه** اشاره می‌کنند |
| **Wiring** | چیزی که یک قطعه را به دکمه یا رویداد وصل می‌کند |
| **Motion / Noise** | انیمیشن و صدا |
| **Bring in / Scrap** | وارد کردن فایل و دور انداختن جسم |

## چیدمان

سه ستون روی دسکتاپ، و روی گوشی به یک ستون تا می‌شود (Rack با دکمه باز
می‌شود):

```
┌──────────────── KIMIA Workbench ─────────── Play ›──┐
│ Rack        │      نمای زنده        │   Dossier    │
│ Ground      │                       │  Placement   │
│ Ball        │      (frame.png)      │  Fittings    │
│ ● Model_1   │                       │  Labels      │
│             │                       │  Wiring      │
│ Bring in    │                       │  Bench test  │
├─────────────────── نوار وضعیت ─────────────────────┤
```

نقطهٔ رنگی کنار هر ردیف می‌گوید چه فیزیکی دارد: برنجی = جامد، سبز = متحرک،
خاکستری = فقط تزئین. کنارش هم شمارش برچسب/حرکت/صدا نوشته می‌شود.

## کار کردن با آن

۱. **Bring in** — مسیر فایل `.obj` یا `.fbx` را می‌دهی و اندازه‌ای که
   می‌خواهی به متر. موتور خودش فایل را به آن اندازه می‌نشاند، هر واحدی که
   داشته باشد. Dossier اندازهٔ **اندازه‌گیری‌شده** را نشان می‌دهد نه ضریب
   خام، چون ضریب برای کاربر معنایی ندارد.
۲. **Fittings** — نوع بدنه را انتخاب می‌کنی: `static` (دیوار)،
   `dynamic` (هل داده می‌شود)، `sphere` (می‌غلتد) یا هیچ. **بلافاصله**
   اثر می‌کند؛ ویرایشگر باید نتیجه را نشان بدهد نه اینکه بگوید دوباره اجرا کن.
۳. **Labels** — `enemy`، `cover`. یک برچسب به یک گروه اشاره می‌کند بدون
   نوشتن نام هیچ‌کدام.
۴. **Wiring** — نام کلیپ و **دکمه**‌اش را می‌دهی (`k`) یا رویداد بازی
   (`goal`, `kick`, `tackle`, `whistle`). همین برای صدا هم هست.
۵. **Bench test** — سیم را همان‌جا می‌کشی و می‌بینی چه اجرا می‌شود، بدون
   اینکه از ویرایشگر بیرون بروی.

## معماری

صفحه هیچ‌چیز از موتور نمی‌داند. سرور درخواست را به لایهٔ `studio`
می‌دهد، آن از `WorldEditor` سؤال واقعی می‌پرسد، و JSON برمی‌گردد. یعنی هر
تصمیمی در موتور می‌ماند جایی که **تست‌پذیر** است، و صفحه فقط یک نما است.

مسیرها: `/api/rack`, `/api/dossier`, `/api/place`, `/api/paint`,
`/api/fit-body`, `/api/label`, `/api/unlabel`, `/api/labelled`,
`/api/wire-motion`, `/api/wire-noise`, `/api/unwire`, `/api/bring-in`,
`/api/scrap`, `/api/pull`, `/api/pulse`.

مسیر ناشناخته یا نام اشتباه، `{"ok":false,"error":...}` برمی‌گرداند نه
خطای سرور — یک صفحهٔ قدیمی هرگز نباید موتور را قفل کند.

**صفحه کاملاً خودکفاست:** نه CDN، نه فونت بیرونی، نه فایل جانبی. روی گوشی
بدون اینترنت دقیقاً مثل دسکتاپ کار می‌کند.

## قفل‌ها

API روی نخ سرور اجرا می‌شود و حلقهٔ اصلی هم‌زمان دنیا را جلو می‌برد، پس هر
دو یک قفل می‌گیرند. حلقهٔ اصلی قفل را **قبل از** تماس با سرور رها می‌کند؛
اولین باری که این رعایت نشد، `/api/pulse` قفل کرد (lock-order inversion).
